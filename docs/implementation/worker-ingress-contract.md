# Worker ingress contract — local executable boundary

## Authority and scope

Separately authorized local implementation authority hardening atop baseline `ed0401d6dde4a3d8ba02d882beb72bf9e25f0cdf`. Historical documentation-only exclusions remain applicable outside this local slice. `src/worker-ingress.ts` exports a reusable class with `handle(Request)`; it is **not a Worker entrypoint**, has no default export or production `fetch`, deployment configuration, public endpoint or real verifier. Tests construct Requests inside an in-memory test-only Worker service-binding RPC harness. Real existing shared `Processor`/D1 acceptance commits state and pending outbox atomically. No policy duplication, consumer, provider, UI, resource mutation, deploy, commit or push is included.

## Trust boundary and lifecycle

1. Generate an internal UUID request ID (ignore external correlation headers).
2. Require POST, exact `/v1/ingress/{provider}` with provider `[a-z][a-z0-9_-]{0,31}` and no query. Version 1 is the only route version.
3. Require `application/json` (optional UTF-8 charset); reject Content-Encoding. Read the stream with a 16,384-byte limit, cancel on overflow, never trust Content-Length as the actual size. Broken streams reject safely. Fatal UTF-8 decode precedes JSON parsing.
4. Reject duplicate decoded JSON property names, including escaped-equivalent names, before JSON.parse can silently choose the last value. Inspect all object nesting; depth greater than four fails. The lexical inspection is not a replacement JSON parser: JSON.parse still rejects malformed syntax. Unknown fields (including tenant_id/environment/source_binding) fail at top level and qualification level.
5. Reuse `validateInput` for required exact fields, types, safe positive sequence integers, schema 1, mock channel, real UTC calendar timestamps and synthetic enum vocabulary. Add ingress-only limits: source event/lead/contact references `[A-Za-z0-9_.:-]{1,128}`, text at most 4,096 UTF-16 code units; occurred_at at most 24 characters. Shared location normalization/120-character trimmed limit and null-versus-omitted semantics remain unchanged. Total UTF-8 byte limit applies independently. Text may be empty; no free-text interpretation.
6. Hash exact raw bytes using pinned portable SHA-256. Invoke mandatory injected verifier with provider, method, path, headers, copied raw bytes and digest. There is no default verifier, no always-accept production implementation and no header-based tenant lookup.
7. Capture immutable verified principal metadata. Require provider/method/path/body digest to match the actual request. Principal/source/nonce must be bounded opaque reference strings; signed_at must be valid UTC, at most 24 characters, within 300 seconds past or 30 seconds future of the injected server clock, inclusive. These are test policy constants, not selected-provider limits. occurred_at is informational fact time; it is not freshness/ordering authority. Freshness binds the **authenticated signed_at**, never an unverified body/header timestamp.
8. Retrieve server-side source mappings by verified authority. Require exactly one result, not a default or first match. Its principal, provider and source must exactly match the verifier's authority. Require development environment and action `ingest_mock_lead`; authentication alone is not action authorization. Capture the mapping ID and exact version before further awaits. Require its status ACTIVE, valid positive safe-integer version and exact verified principal/provider/source/environment/action. Missing/ambiguous/wrong-source/wrong-action/inactive/revoked mappings fail closed. Resolution and acceptance must identify the same original primary D1 binding; different binding objects fail closed, even if wrappers claim the same underlying database. Active tenant is checked before nonce binding; acceptance checks tenant activity and the complete captured source authority inside coherent reads and atomic writes, including replay.
9. Atomically bind scoped nonce identity to exact authenticated request identity; conflict rejects before core. Then call the shared Processor with trusted mapping-derived context, validated data and the captured source authority. The processor forwards that unchanged authority on every bounded retry; it never refreshes a stale mapping into a new grant. Core retains semantic fingerprint, event idempotency, sequencing, qualification and atomic D1/outbox invariants. No untrusted tenant reaches it.
10. Return 200 only after durable acceptance or immutable replay. Reply contains generated request_id and original internal event_id, not payload/qualification/tenant/provider identifiers. No external effects occur.

## Verification abstraction and future protocols

`Dependencies.verifier.verify` returns null or a `Principal`: principal, provider, source, signed_at, nonce, body_digest, method, path. This is a **trusted adapter output**, not a structure callers may supply as authorization. Adapter implementations must establish all those claims cryptographically or through an explicitly approved equivalent protocol. An OAuth token alone does not bind request bytes/source/time/nonce; a shared-secret header alone does not satisfy this contract. Future signatures, shared secrets and OAuth need reviewed authority, request-binding and replay mechanisms behind this interface. The raw body copy prevents adapter mutation of the bytes used for validation/hash.

Only test harnesses implement synthetic verification. Source mappings now have a real local D1 persistence adapter; synthetic tenant/mapping setup remains test-only, without an administration endpoint. They deliberately fabricate trusted metadata for control-flow tests; this is not proof of authenticity against any real protocol. Production adapter registration/credential scopes, provider canonicalization, key rotation, constant-time secret handling, OAuth audience/expiry/scopes, signature/timestamp coverage and source ownership remain blockers for real ingress.

## Persisted source authority and acceptance cutoff

`src/source-mappings.ts` defines the provider-independent `SourceMappingStore`/`SourceAuthority` contract and local `D1SourceMappingStore`. Each mapping stores generated UUIDv4 ID, monotonically increasing integer version, provider/source, authenticated principal, tenant FK, source binding, authorized operation/environment, ACTIVE/INACTIVE/REVOKED status, created/updated timestamps and terminal revoked timestamp/version. `(provider, source)` is globally unique: a routed source cannot ambiguously belong to two tenants or principals. No tenant/default is inferred from input. The store returns defensive frozen row copies, not live configuration objects.

The additive definitions live in the existing packaged `src/schema.sql`: source mappings, version/tombstone triggers, and the separate batch-local `authority_assertions` table. Reapplying this schema installs the new objects without altering existing tables or dropping data. Tests apply it only to local bindings. There is no automatic remote migration, resource creation or rollout approval.

Local trusted setup uses `store.create(mappingFields)`, `store.update(scope,id,expectedVersion,{principal?,source_binding?,status?})`, and `store.revoke(scope,id,expectedVersion)`. These are maintenance primitives, **not an administrator authorization API**. Values are parameter-bound; create/update keys have fixed allowlists. Update/revoke compare tenant, ID and expected version in one `UPDATE ... RETURNING` statement. A foreign tenant, stale version or terminal revoked row yields sanitized typed denial. Updates advance version exactly once; inactive-to-active regrant explicitly advances version. The API cannot change tenant/provider/source/ID/creation identity. Direct trusted SQL movement of tenant ownership must also advance version and is rejected by an in-flight old authority; it is not an exposed transfer operation.

Physical deletion is prohibited by a persistent trigger, and REVOKED is terminal. A BEFORE INSERT collision trigger also rejects INSERT OR REPLACE/route or ID replacement, independent of SQLite recursive-trigger settings; REPLACE cannot silently delete a tombstone and restore an old active version. Routing tombstones permanently reserve provider/source; creation cannot recycle an old mapping ID/version or recreate that route. An update trigger rejects unchanged/reset/skipped versions, immutable routing/ID/creation changes, unsafe integer overflow and any mutation of a revoked row. Revocation does not erase accepted business records or retract already committed outbox intents. A future transfer/purge/regrant policy for terminal revocation needs separately reviewed design rather than bypassing these triggers.

`Ingress` requires matching persistence identities, and `Processor.process(...,authority)` passes the exact frozen authority to `AcceptanceRepository.accept(...,target,authority)` on every attempt. D1 checks **all** captured ID/version/provider/source/principal/tenant/source-binding/operation/environment fields and ACTIVE status, not version alone. Tenant/activity and source authority reads are in the same transactional batch as the exact event/lead/qualification snapshot. Duplicate replay linearizes at that coherent read batch: revocation committed before the snapshot denies even a previously accepted event; a replay read completed before revocation may return its original immutable outcome. There is no cached-success authorization shortcut.

New/update acceptance linearizes at the **actual atomic D1 write batch**. A named SQL CHECK requires the same full authority tuple to exist ACTIVE before any business writes. Zero authorization aborts the entire batch; JavaScript does not attempt to roll back after success. A change or revocation that commits before this batch produces zero new business/outbox effects, even if resolution, verification or planning already succeeded. Independent requests and mapping mutation serialize through the same primary database: acceptance completed first may succeed; revocation completed first must deny. A second asynchronous lookup before calling Processor would not satisfy this contract and is not the authority cutoff. Existing lead/event CAS, identity conflicts, bounded transient classification and ambiguous-commit reconciliation are unchanged. Source denial is a nonretryable context failure; a transport retry retains the original authority rather than silently granting a changed version.

No-authority SQLite/core and existing trusted D1 maintenance paths retain their original behavior. They are not authenticated ingress paths. The processor rejects supplied authority if the repository lacks authority capability; ingress rejects a missing/mismatched capability. Trusted custom adapters must enforce the same atomic persistence contract, not substitute an out-of-transaction memory callback. Binding identity is a compatibility check, not proof that arbitrary trusted adapter code is honest or that a wrapper secretly hiding a session is primary.

## Immutable composition, mutable authorization data

`Ingress` captures collaborator objects and bound verifier/resolve/replay/repository methods once at construction into frozen narrow facades held in a runtime `#private` field. Replacing the caller's dependency object, collaborator objects, method properties, clock or logger during any await cannot rewire that instance. The D1 repository and mapping store capture their original binding methods, generator/clock identities and policy in runtime `#private` fields; repository helper methods are private too. No caller-owned global D1 object is frozen, so the emulator and platform receiver semantics remain intact.

This freezes wiring, **not source authorization data**. Legitimate persisted mapping changes remain visible and must invalidate captured stale authority. Injected adapters/functions remain trusted code: their bound receivers or closures must internally capture immutable configuration and must not request-mutate their own database, credentials or policy. A narrow facade cannot make malicious closures honest or deep-clone native platform capabilities. Construct a new ingress instance to deliberately change trusted adapter configuration; only synthetic tests use such recomposition. Runtime tests separately cover original-object/method replacement during verifier, mapping and replay awaits, repository configuration-field assignments, immutable proof/mapping capture and live persisted revocation.

## Replay and recovery contract

`replay.bind(key,digest)` is mandatory: atomically establish the first identity; return true for first or identical subsequent identity, false for conflicting reuse. Errors fail closed. Key is a JSON tuple `(development, provider, principal, source, nonce)`. Digest covers method, path, signed_at, raw-body hash, mapping ID/version, resolved tenant and source binding. Exact authenticated retry is allowed only while authentication/freshness/lifecycle/current versioned source authority still passes; changing any authenticated identity component with the same nonce conflicts. Memory implementation exists **only inside tests**.

Binding is not a one-shot consumption flag. Never delete or mark a nonce irreversibly consumed before durable acceptance: identical retries must be able to retry after precommit failure, ambiguous persistence errors or response loss. No cached success skips current authorization. Ledger implementation must be durable/atomic across isolates and retain conflict information through the acceptance window plus clock-skew and maximum in-flight lifetime. Mapping-version pinning and local atomic revocation are implemented above. Production nonce retention/GC and distributed ledger behavior still require separate implementation and review; no durable nonce store is claimed here.

Core durable identity is `(tenant, source_binding, source_event_id)` with its existing canonical semantic fingerprint. Same event/same semantic input under a fresh valid authentication can return the original internal event/outcome; same event/changed semantic input conflicts even with a new nonce. Exact same-nonce retry is stricter: byte-different JSON conflicts, even when semantic input is equal. After freshness expires, recovery requires newly authenticated delivery with a new nonce and current timestamp; the original semantic event identity remains unchanged. A 503/500 does not prove rollback. Explicit replay reconciles an already committed outcome without duplicate action intent. This test executes real local D1 acceptance and then injects response loss on each allowed application attempt, followed by successful explicit replay.

## Safe errors and closed logging

| Status | Safe code / meaning |
| --- | --- |
| 400 | invalid_input: malformed JSON/UTF-8/schema/stream |
| 401 | unauthenticated: missing/rejected or mismatched verified proof, stale/future authentication |
| 403 | forbidden: missing/ambiguous/inactive/revoked/changed/unauthorized mapping, inactive context |
| 404 / 405 / 415 / 413 | route / method / media_type / too_large |
| 409 | conflict: nonce reuse or core event/sequence conflict |
| 503 | unavailable: existing bounded persistence retry budget exhausted, possibly committed; also known transient mapping-store failure |
| 500 | internal: unexpected/permanent/unknown persistence, resolver/verifier/ledger errors |

Only typed known boundary/core errors are classified; raw database messages, exceptions, causes, headers, payloads, stacks, secrets and PII are never returned or logged. Permanent/unknown failures are not blindly retried by ingress; existing Processor owns bounded acceptance retries. Response headers set no-store and nosniff. All responses carry generated request_id. The log callback receives only `{request_id,status,code}`; no spread of input/exception objects, external IDs or tenant labels. Logger exceptions are swallowed to avoid changing an already committed result; production monitoring of logger health is a future operational requirement.

## Exclusions and remaining real-ingress gates

No production verifier, durable nonce adapter, deployed handler, public endpoint, real signature/OAuth/shared-secret protocol, consumer, SDK, resource, configuration, dependency or credentials were added. A local persisted mapping adapter, atomic acceptance-time source authorization and immutable ingress wiring now close the two previously documented local trust gaps. **Security review: PASS for the local authority-hardening scope**, following the parent's full/focused reruns and independent security/correctness review. No blocking or non-blocking security/correctness findings remain within the documented trusted-adapter contract; this does not authorize production.

Before real ingress, production implementation still requires separately approved identity/protocol policy, reviewed mapping administrative authorization/transfer/purge/retention procedures, isolated original-primary bindings and migration rollout, durable distributed nonce implementation, request timeouts/slow-body defenses, quotas/rate/concurrency limits, observability access/retention, PII retention/deletion and operational failure/reconciliation procedures. Permanent routing tombstones are the conservative local policy, not an approved production retention or source-transfer policy. Nonce binding and D1 acceptance remain separate stores/boundaries; identical recovery is supported, but cross-system atomicity is not claimed. Local bounded byte reads do not establish slowloris/CPU/latency/SLO or distributed correctness. Remote D1, staging and production are NOT RUN; local technical results do not grant activation, security-policy, secret or infrastructure approval.
