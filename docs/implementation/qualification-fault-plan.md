# Qualification fault/build manifest plan

**Immutable offline descriptions implemented; scenario runtime executors ABSENT.** `scripts/qualification-operator-plan.ts` provides a validated fixed S12–S35 variant catalogue, `scenarioManifest`, exact packet/artifact validation and `assertOriginalDatabaseIdentity`. It does not install faults, deploy a Worker, mutate D1, drive requests, reset a coordinator or run these scenarios. All remote cases remain NOT RUN; every returned scenario has `executor=ABSENT`, `remoteReady=false`, `status=STOP`.

Use the [original S01–S37 acceptance matrix](staging-readiness.md#7-exact-acceptance-matrix--all-remote-cases-not-run) as the authoritative oracle. This manifest is not a replacement matrix or new synthetic policy. Resource/closed-deployment, Access/routing and fault/restore approvals remain separate in the [operator plan](qualification-remote-operator.md).

## Immutable selection and trust boundary

`scenarioManifest(input, validatedPacket)` requires exactly:

- A fixed `scenario` S12–S35 and a variant from the immutable catalogue. S36 restore and S37 release containment intentionally are not fault-build variants.
- `packetHash` matching the original minted validated packet, `originalDatabaseId` matching its exact D1 UUID and a lowercase SHA256 `buildHash` for the isolated qualification bundle.
- For S18 only, actual reviewed generated-write `statementCount` 1–64 and 1-based `failureAfterStatement` 1–count. Every statement position requires a separate clean run, including assertion-table deletes, freshness guards and CAS assertion positions in the actual generated array. Zero fields are mandatory for all other scenarios. The supplied count is bounded but **not** measured or certified by the planner; the executor must enumerate the real array and record its immutable hash.

The frozen result binds the input and instrumentation requirements into `manifestHash`, caps application attempts at four (one for S24/S25 `zero-retries`), and preserves the original immutable deadline. This cap is a ceiling, not permission to retry unknown errors: no-retry failures must still stop at one. Claim and acceptance attempt counters must be separate, with issued/resolved/rejected markers per original operation and no hidden retry/reconcile reads. Counters must be checked against the actual retry owner, not an outer test loop.

Only a future reviewed **private build-time composition** may select a scenario. There is no request-selected fault, clock, policy, tier, tenant, source, namespace, DB or grant. Unknown manifest fields reject; no public/admin path or fault header exists. A test's `buildHash` format is not proof the corresponding runtime mechanism exists; an approved fault action must name packet hash, manifest hash, qualification bundle hash, statement array hash when applicable, transport scope and bounded budgets. Do not upload a normal release with runtime test knobs or treat an admin-authenticated request as trusted scenario selection.

Maintain the exact original D1 object in repository, replay ledger and issued observer. `assertOriginalDatabaseIdentity(original,[repositoryIdentity,replayIdentity,issuedObserverIdentity])` checks reference equality and rejects a session-like original exposing `getBookmark`. It does not discover identities or prevent a privileged collaborator from lying about them; the actual composition must capture and validate these identities and bind methods before instrumentation. Never replace DB with a session or a wrapping binding and then claim original-primary semantics. A future trusted instrumentation seam must observe around the captured original `batch`/claim operation with the same identity, not mutate public collaborators or let external input substitute a clock.

Do not renew deadlines on restart, retries, delayed result, lost response or clock changes. JavaScript cannot sample a clock inside a running SQL batch; the trusted last pre-batch observation and final SQL DB-time guard remain inside the documented acceptance boundary. Do not weaken any guard to manufacture the oracle.

## Per-run evidence contract

Before a run, record packet/manifest/build/source/config/migration/statement-array hashes, separately authenticated approval references, exact synthetic fixture scope, original DB UUID, namespace and fixed object name. Capture the scenario-specific policy hash from the reviewed policy owner's artifact; a textual tier or request flag is never authority. The planner does not itself certify that policy artifact or an initializer.

Capture a protected same-primary pre-state, generated request indices (not payload logs), actual operation/attempt/issuance/settlement ordering, safe response statuses, readback after settlement and before disposal, and explicit signed replay after ambiguity when its original deadline still permits it. Readback must include immutable event/outbox/replay/revocation row hashes as required, counts/FKs/assertion emptiness, foreign-tenant unchanged state, coordinator pending/charged state and immutable deadlines. Failure to observe any required state is UNKNOWN, not zero effects. Do not sum grouped variants as independent test executions unless distinct real runs were performed.

The original binding remains identity authority, not a serialized UUID alone. Bounded observers must retain pending work through timeout and make no unbounded captures of SQL/body or owner data in general logs. Private detailed evidence uses restricted permissions and approved retention. No automated fixture cleanup may delete tombstones or coordinator charges to make the next run pass; use separately approved isolated fresh scope while preserving all historical ownership.

Contain on uncertainty: disable ingress/effects, stop initiating writes, retain charged work, preserve actual failed logs and same-target evidence. Keep finite tombstones and indefinite charged quarantine as already approved; no reclamation, takeover, epoch/namespace replacement or store reset. S36 restore requires protected latest replay/revocation history and separate recovery approval; no D1 restore before preservation, no blindly repeated apply/import, no reopening after lost history. S37 must independently verify normal bundle/config excludes every fault mechanism and any privileged private initializer after sealing.

## What remains absent

No actual S12–S35 remote executor, barrier scheduler, SQL-failure instrument, delay controller, private trusted clock runtime, fault deployment, approved protected transport driver, cross-region caller, platform termination/CPU mechanism or replay-preserving restore/reconciliation tool is delivered here. This is intentional and explicit, not a claim that every case is remote-ready. Existing local component tests and sibling-owned policy/private-initializer work may provide separately reviewed seams, but only demonstrated integration can change their status. Some remote platform faults may have no supported controlled mechanism: obtain documented capability and evidence or mark STOP, never substitute mocks.

Offline verification here proves narrow validation, immutability, exact target/hash binding, bounded attempts, rejection of request/clock/tier overrides and executable read-only SQLite catalogue/comparison. It proves no remote state or remote fault outcome. Full regression, packaging, integrated runtime qualification and final independent review remain parent-owned. Historical DA11 uncertainty remains accepted for offline/local work and UNKNOWN in cause; these planners do not revisit it.
