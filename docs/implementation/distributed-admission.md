## 1. Requirement and alternatives

An exact aggregate cap is necessary here because the staging plan explicitly requests a strict bound on post-authentication pipelines across Worker instances, rather than approximate per-location protection. It is **not** necessary for authentication, tenant isolation, semantic idempotency or atomic state/outbox correctness; those remain D1 responsibilities. Global here means all participating ingress instances in one environment/admission domain, not all environments combined, all CPU, preauthentication work, or all D1 queries including maintenance.

| Option | Decision and rationale |
| --- | --- |
| Single SQLite-backed Durable Object coordinator | Selected for offline qualification: one serialization authority for all three counters, private persistent bounded registry, small explicit async capability and no new D1 business schema. It is a throughput/latency bottleneck and failure domain by design; no measured capacity or remote availability claim. |
| Single original-primary D1 coordinator | Defensible alternative: counters, owner records and conditional acquire/release in one guarded batch, with durable duplicate handling. Shares application DB contention/outage; needs tables/triggers/atomic assertion design and still cannot auto-free uncertain active work. Not rejected as impossible, but larger scope and conflicts with the minimal DO direction already proposed in staging. A read then a separate UPDATE is not sufficient. |
| Per-tenant/per-source DOs with a sampled aggregate, KV, edge rate binding or isolate counters | Rejected for exact aggregate admission: independent decisions cannot atomically test/increment the aggregate and subordinate limits. |
| Hierarchical global reservations delegated to shards | Could conservatively partition a hard bound if one root serially allocates non-overlapping durable capacity and never unsafe-reclaims it; not inherently impossible. Dynamic exact utilization and cross-level rate/tenant decisions require a distributed protocol and waste capacity on loss. Not the minimal slice. Non-atomic check-global-then-check-source is rejected. |

The **logical global capacity authority must serialize** competing allocations (DO or D1); it need not run all pipeline work. Multiple namespace names, tenant-selected objects or a new object per code version defeat this invariant. No sharding/fallback/load-balanced coordinator IDs in this design.

## 2. Trusted composition, identity and capability

Keep `LocalAdmission.enter/source` and synchronous `RatePolicy` as isolate-local protection, not replace them with a Promise-shaped counterfeit. Retain preauth/body/chunk/crypto bounds, original safe envelopes, fixed request deadline, and captured methods. Add a separate optional, narrow **async distributed-admission capability** to trusted operational composition, preserving legacy local-only construction. Explicit distributed mode requires the capability; missing/invalid capability cannot silently become local mode.

Conceptual operations (names are design contracts, not implemented APIs):

- `reserve(context, attempt)` → granted immutable reservation, definitive denial, or unknown transport outcome.
- `start(ownerHandle)` → started acknowledgement for this execution, terminal/no-start, or unknown.
- `inspect(ownerHandle)` → exact owned state or unknown/not-found; never foreign state or success authority.
- `cancelUnstarted(ownerHandle)` → atomically seal an unstarted/absent attempt where storage capacity permits; never cancel ACTIVE.
- `settle(ownerHandle, terminalEvidence)` → idempotent release only after the trusted owning execution establishes actual terminal completion of all work it issued.
- Internal trusted reconciliation is a separate maintenance capability, **not** exposed on ingress/public HTTP or included in request-selected controls. No remotely usable admin tool is required for Phase 2.

Capture bound methods, environment, fixed namespace/object name, policy and original DB identity once into private facades. Do not freeze platform objects or keep request objects, promises or DB wrappers in Worker module globals. Preserve platform receivers. Trusted binding possession is the capability boundary; no header token, URL, tenant claim or HMAC key ID selects an object, quota tier, administrative action or admission environment.

Call only after proof validation, exact current mapping resolution and active-tenant `assertScope`, before nonce claim/Processor work. Existing local source protection may precede the scope await as today, but **distributed tenant/source charging does not**. Capture the full original mapping tuple; never refresh it during retries. Source key is a domain-separated hash of compact JSON `[environment, provider, principal, source]`, derived from immutable validated proof/mapping. Tenant key is the mapped UUID and environment. Neither mapping version, key ID nor request nonce selects a new source bucket; key rotation cannot reset usage. Authorized changes to stable principal/source identities require policy review, not an automatic quota reset feature.

Each HTTP execution generates its own unpredictable UUID attempt ID and owner capability (at least 128 random bits), *before* the first coordinator call. Admission attempt identity is not the authentication nonce or semantic event identity. Bind record to environment/domain, tenant, stable source, complete authority fingerprint and owner capability; conflicting reuse fails closed. No raw HMAC proof, nonce, body, contact, signature or signing key in coordinator storage/logs. Owner capabilities are restricted control metadata, never returned to HTTP callers or logged. Cryptographic owner tokens are not provider credentials and must never be copied into D1 or public evidence.

A caller retry is a new execution/owner requiring a new counted permit, even for identical nonce/event. Existing D1 replay and semantic identity reconcile business outcomes. A new Worker cannot adopt a previous ACTIVE handle and launch work with it. Inspection/retry of `start` is control recovery only: one retained owning execution has a private once-only launch latch; no duplicate callback launches a second pipeline. Trusted arbitrary adapter code remains trusted, not magically validated by structural types.

## 2a. Normative closed codec (version 1)

This is a small explicit schema/codec, not a generic RPC serialization framework. **All** operations, replies and durable state use canonical JSON bytes only; transport types or TypeScript annotations are not validation. Names `reserve/start/inspect/cancelUnstarted/settle/quarantine/reconcile` below are the complete operation set (`reserve` is acquire; `settle` is release). Quarantine is an internal diagnostic/control transition; reconciliation is a separate trusted maintenance capability, never an ingress-selected method.

### Primitive and encoding rules

Notation `{a:X,b:Y}` means precisely those own fields, all required; no optional keys, inherited fields, symbols or extra properties. A union is closed by its literal tag. `null` is permitted only where stated. Numbers are primitive finite safe integers, never strings, fractions, NaN, Infinity, negative zero or boxed values. `Time` is integer epoch milliseconds 0..8,640,000,000,000,000; all additions must stay in that range. `Count` is 0..10,240,000 (further restricted by policy/invariants); `Version` is 1..9,007,199,254,740,990. `UUID` is lowercase canonical UUIDv4, including version/variant bits; `Digest` is exactly 64 lowercase hexadecimal ASCII characters. `Token` is exactly 32 lowercase hexadecimal ASCII characters from at least 128 cryptographically random bits, independently generated as an owner capability, not a caller-chosen credential; attempt IDs are separate UUIDv4 values. `Fence` is canonical decimal ASCII `0` or `[1-9][0-9]{0,19}`, at most 18446744073709551615; zero means provisional only, positive fences are coordinator-issued monotonic identities. Never convert fences through a floating-point number; exhaustion denies fresh owners, never wraps. `Name` is `[A-Za-z0-9_.:-]{1,128}` ASCII. `Env` is exactly `development|staging`; `Domain` is the single trusted composition literal `distributed-admission-v1`; `Op` is exactly `ingest_mock_lead`. Enum notation uses literal strings, not a string containing pipes.

Canonical encoding: sorted ASCII object keys recursively, arrays in specified order, no whitespace/BOM/newline; decimal integer numbers without exponent; strings contain printable ASCII only, escaping quote and backslash minimally, no alternative Unicode/slash escapes. UTF-8 is therefore ASCII. Decode bounded bytes with fatal UTF-8, JSON parse, full schema validation, and require canonical re-encoding to equal the original bytes **exactly** before accepting. This rejects duplicate JSON keys (including escaped aliases), whitespace, alternative numeric syntax and trailing data without a custom duplicate-key parser. Internal clients use this same codec; accepting arbitrary third-party JSON is not required. No dates, buffers, BigInt wire values, class instances, Map/Set, functions, undefined, Error objects, cycles or arbitrary RPC types. Maximum request or response body is **8,192 bytes**, nesting depth 8; durable canonical state maximum **65,536 ASCII bytes**, depth 10. This is a conservative local representation ceiling, not a production quota: the inherited 4-MiB single-key proposal exceeds the current official SQLite-backed key+value limit of 2 MB, and pinned workerd must still be qualified. Wire/state arrays only appear in the state shapes below, at most 1,024 elements each (the local fixed four-element source-hash tuple is not a message field); object key counts follow their exact schema. Reject before buffering beyond limits. Effective representable capacity is the lesser of field/count and total-byte bounds. Before allocating a fresh record, reserve its worst-case encoded lifecycle growth (longest state/terminal-kind strings and maximum-width timestamps) plus bounded metadata growth for all retained records; never consume headroom needed for existing start/cancel/quarantine/settle transitions. Deny `state-size` before mutation if that envelope cannot fit. Settlement still needs available storage; storage-write failure retains charge, never claims release.

For trusted objects before serialization (including policy/capability result objects), first inspect prototype and all own property descriptors: plain Object/null prototype, exact own string keys (including non-enumerable keys), enumerable own data properties only, no getters/setters/symbols. Arrays must have Array prototype, own dense data indices and length only, no custom properties/accessors. Capture every permitted own value **once**, recursively validate the complete snapshot, and only then create/freeze private immutable copies. Never spread/project first, invoke getters, accept inherited fields or re-read collaborator fields later. Proxy traps/descriptor failures are a failed trusted-composition boundary; proxies are not a supported trusted input and structural validation does not authenticate malicious collaborators. Freeze copies, not platform bindings; capture bound platform methods and original namespace/DB identity once.

### Exact shared structures

- `Authority = {environment:Env,tenant:UUID,provider:Name,principal:Name,source:Name,mappingId:UUID,mappingVersion:Version,sourceBinding:Name,operation:Op}`. It is the complete captured active mapping authority tuple, not a request claim or a partial fingerprint. Mapping lifecycle checks remain in D1; no proof/nonce/key/body is transmitted.
- `Context = {authority:Authority,domain:Domain,policyEpoch:UUID,policyDigest:Digest,sourceKey:Digest}`. Compute `sourceKey` as lowercase hex SHA-256 of ASCII `apacely-distributed-source-v1:` followed by canonical JSON `[environment,provider,principal,source]`; map version/key ID cannot reset its bucket. `policyDigest` is SHA-256 of canonical policy bytes. Local DB binding equality is a private identity check, **not** a serializable string claimed by the caller.
- `Ticket = {context:Context,attempt:UUID,owner:Token,requestDeadline:Time,reservationTtlMs:Duration,diagnosticTtlMs:Duration,fence:Fence}` where `Duration` is 1..30,000. Before reserve, capture trusted original request deadline and fixed policy TTLs once. Fence is initially `0`; never renew deadline/TTLs on retries. `Handle` is a Ticket with positive fence. Registry comparison includes every field, full authority and owner, not only attempt/fence. A handle is private to the original execution; no replacement execution adoption.
- `Policy = {version:1,environment:Env,domain:Domain,epoch:UUID,aggregateCap:Limit,tenantCap:Limit,sourceCap:Limit,tenantKeyCap:Limit,sourceKeyCap:Limit,recordCap:Limit,aggregateRate:Rate,tenantRate:Rate,sourceRate:Rate,windowMs:Window,reservationTtlMs:Duration,diagnosticTtlMs:Duration,controlAttempts:Attempts}`. `Limit` is 1..1,024, `Rate` 1..10,000, `Window` 1,000..60,000, `Attempts` 1..4. This minimal v1 uses uniform tenant policy only; a per-tenant map would require a separately reviewed schema/version, not arbitrary dictionary extensions. Policy and epoch are immutable for this fixed object/state; no policy-selected new object or reset.
- `Record = {handle:Handle,state:State,reservedAt:Time,reservationExpiresAt:Time,startedAt:Time|null,diagnosticExpiresAt:Time|null,terminalAt:Time|null,terminalKind:TerminalKind|null}`. `State` is `RESERVED|ACTIVE|QUARANTINED|CANCELLED|EXPIRED|RELEASED`; `TerminalKind` is `cancelled|expired|known-not-issued|all-issued-terminal`. `reservationExpiresAt=min(requestDeadline,reservedAt+reservationTtlMs)`; start must precede both immutable deadlines. ACTIVE/QUARANTINED have startedAt and `diagnosticExpiresAt=startedAt+diagnosticTtlMs`, no terminal fields; RESERVED has all nullable fields null; CANCELLED/EXPIRED have terminalAt and matching terminalKind, no start fields; RELEASED has terminalAt and a settlement kind, with start fields both null for known-not-issued unstarted work or both present for started work. Timestamps must be within bounds, startedAt >= reservedAt and < reservationExpiresAt/requestDeadline, terminalAt >= reservedAt and any startedAt; EXPIRED requires terminalAt >= reservationExpiresAt. A late ABSENT cancellation seal may have reservedAt > requestDeadline, so its expired reservation bound is not live authority. known-not-issued cannot claim any issued work; all-issued-terminal requires startedAt. Cancelling ABSENT allocates a positive fence/tombstone with reservedAt at seal time and the same original ticket fields; it never creates launch authority. Terminal fields become immutable once written.

### Exact operation request/reply unions and ownership matching

`Request = {version:1,operation:Method,ticket:Ticket,payload:Payload}`. Method determines the only permitted payload: reserve/start/inspect/cancelUnstarted/quarantine use `{}`; settle/reconcile use `{kind:K,barrierId:UUID}` with `K=known-not-issued|all-issued-terminal`. For malformed requests that cannot produce a valid ticket, the only reply is `Rejected={version:1,result:{tag:"fault",code:"invalid-message"}}`, HTTP 400; this distinct exact envelope never grants/retries or echoes attacker fields. All valid requests use Reply below. Reserve requires fence 0; start/settle/quarantine/reconcile require positive fence; inspect/cancelUnstarted allow 0 for reserve-response-loss recovery. Original ticket is unchanged for reserve replay; positive handles never replace immutable original fields. These are not caller-selectable reconciliation or settlement permissions.

`Reply = {version:1,operation:Method,ticket:Ticket,result:Result}` echoes the **exact request** ticket and method. Result is one of:

| Tag / exact fields | Allowed meaning |
| --- | --- |
| `{tag:"record",record:Record}` | Owned durable state, after confirmed transaction; reserve: RESERVED or original ACTIVE/QUARANTINED/terminal replay, start: ACTIVE/QUARANTINED or terminal, inspect: any state, cancelUnstarted: CANCELLED/EXPIRED or existing ACTIVE/QUARANTINED/RELEASED, quarantine: QUARANTINED or terminal, settle/reconcile: RELEASED or original terminal. Returning ACTIVE from cancel is not cancellation success; returning QUARANTINED from start is not launch authority. |
| `{tag:"absent"}` | inspect only; not rollback/sealing proof. |
| `{tag:"denied",reason:D,retryAfterSeconds:N}` | `D=aggregate|tenant|source|rate-aggregate|rate-tenant|rate-source|keys|records|deadline|clock|ownership|policy|invalid-state|not-terminal|not-authorized|fence-exhausted|state-size`; N is integer 1..60 only for a rate reason, otherwise null. No foreign record or actual foreign handle attached. |
| `{tag:"fault",code:C}` | `C=invalid-message|storage-corrupt|unavailable|internal`; never carries exceptions, arbitrary text, payloads or a claimed rollback. |

The client validates the **entire** reply union, permitted method/result/state combination and exact echoed ticket before interpretation. Before responding, the coordinator applies the same entire request/context/policy/record matching checks; malformed messages allocate/mutate nothing. Record handle must equal the request ticket in every field; only a provisional fence 0 may be replaced by a positive fence during exact reserve/inspect/cancel recovery. Thereafter every response must match the retained positive fence exactly. Grant/start must additionally match trusted policy/context, original ownership, deadline, TTLs and valid timestamp relations; only a RESERVED grant followed by exact ACTIVE start permits the original private once-only launch latch while its original deadline is still open. A duplicate reserve returning ACTIVE is recovery, never permission to relaunch. No absent/denied/fault/terminal/reconcile response authorizes a business stage. Context/owner mismatch denies without disclosing stored fields or mutating counters.

**Settlement evidence is not a JSON assertion of truth.** The private original-owner operation tracker and captured actual D1/replay binder issue a barrierId only after known-not-issued or all-issued-terminal proof over every actual issued unit; its private capability checks match original handle, binder, execution and sticky uncertainty before it can construct/send settle. The DO trusts that captured adapter capability, not an HTTP field or caller's `kind` claim; wire schema alone cannot prove D1 termination. Reconcile has a separate captured maintenance binder with an actual validated all-work proof (synthetic barrier only in Phase 2). Without such authority/evidence, no settle/reconcile invocation is permitted; uncertainty calls quarantine or keeps charge, never fabricates a barrier. No public admin route/token or remotely asserted proof is added.

### Durable state schema and validation boundary

The sole fixed key `distributed-admission/state/v1` stores the canonical JSON **string**, not arbitrary structured-clone objects. `PersistentState = {version:1,policy:Policy,policyDigest:Digest,nextFence:Fence,clockHighWater:Time,windowStartedAt:Time,aggregateLive:Count,aggregateArrivals:Count,tenants:TenantEntry[],sources:SourceEntry[],registry:Record[]}`. `nextFence` is positive, strictly greater than every stored fence; allocate only while increment stays within the Fence maximum, otherwise deny fresh owners; never reset/reuse. `TenantEntry={tenant:UUID,live:Count,arrivals:Count}`; `SourceEntry={sourceKey:Digest,tenant:UUID,live:Count,arrivals:Count}`. Arrays are strictly sorted by tenant/sourceKey/handle.attempt respectively, unique, within policy key/record bounds, including historical associations. Entries are not arbitrary property dictionaries. Registry fences are unique; every record matches state environment/domain/epoch/digest and TTL policy, and its recomputed sourceKey matches authority; each source maps to one tenant. A source/tenant reassignment against a historical entry denies instead of overwriting identity. Empty live buckets remain bounded historical entries. Policy digest is recomputed; supplied immutable trusted policy must equal persisted policy exactly.

Inside **every** transaction, validate bytes/schema/invariants before deriving transitions and before any write; validate and canonical-encode candidate state again before put. Startup applies the identical validator. Registry is authoritative for live ownership: bounded full scan (at most R<=1,024) recomputes charged RESERVED/ACTIVE/QUARANTINED G/T/S counts and compares all persisted live counters. Incremental counters are only atomic validated caches, never independent authority; temporary bounded lookup maps permit linear accounting scans, but canonical sorting also costs O(R log R + tenant keys log tenant keys + source keys log source keys). Repeated per-bucket registry scans are quadratic, not the linear behavior implied by the inherited design. The fixture is bounded, not a measured production CPU/throughput qualification. Counts never exceed policy caps, underflow or disagree; aggregate arrivals equals sums of tenant/source arrival counters, each within rate caps, high-water >= windowStartedAt. Rollover keeps the same historical arrays and sets all arrivals to zero atomically while advancing windowStartedAt by whole windowMs multiples; live counters/records never reset. Arrival history is authoritative persisted window accounting, **not** reconstructed from live registry (owners survive rollover); replay does not change it. Malformed/missing/foreign metadata, unrecognized version, duplicate registry entries, impossible times or counters is storage-corrupt: fail closed and do not write, rebootstrap, drop permits or reset counts. An undefined whole key is accepted only by explicit first local test bootstrap with fresh dedicated persistence identity; a later missing key on an initialized identity is corruption, not empty state. No request-triggered initialization. A corrupted state blocks even release until integrity is restored under separately approved maintenance; valid state allows exact terminal settlement despite clock rollback/saturation.

### Fixed internal fetch transport and error classification

Prefer the **installed Miniflare/workerd real DO `fetch`** path, avoiding newer RPC serialization/types. Trusted captured namespace chooses `idFromName("distributed-admission-v1")` once and a fixed stub via `get`; no request URL/environment/tenant chooses a namespace/name. Only POST to `https://admission.internal/v1/{reserve,start,inspect,cancelUnstarted,settle,quarantine,reconcile}` with no query/fragment, no redirect follow and exact operation/route agreement. The trusted transport facade privately owns the stub/namespace and exposes only captured validated operations: no raw fetch/stub access reaches caller/request code. Settlement and maintenance entry points require their respective actual binder capabilities before serialization; barrierId is correlation, not bearer authority, and no remote-proof oracle is assumed. Reconcile is unreachable through ingress facade; no deployable public/default export is added. Method/path/content type mismatches allocate nothing. The URL is a fixed internal stub address, not arbitrary network egress.

Request and reply Content-Type must be exactly `application/json`; no content encoding. Read both bodies via bounded streaming reader, cancel on exceeding 8,192 bytes, reject fatal UTF-8/truncation/invalid canonical JSON, and never use unbounded `text()/json()` before enforcing length. Content-Length, if present, is canonical decimal 0..8,192 and must equal actual bytes, not a buffering exemption. Reject observable duplicate Content-Type/Content-Length headers, including combined comma values; Header APIs cannot prove absence of duplicates already normalized away, so do not claim raw-wire duplicate detection. The trusted internal sender emits one value only; schema/canonical-body validation remains mandatory. Only HTTP **200** with record/absent, **409** with denied, **400** with invalid-message, **503** with unavailable, or **500** with storage-corrupt/internal fault are valid pairs. Everything else (redirect, other status, wrong tagged result/header/body) is malformed, never success. No secrets, body/handle/context/error values or URLs from errors in logs; only existing safe failure envelopes.

A local timeout/transport rejection is an unknown control outcome, not a wire result or rollback proof. Decode only the above closed safe fault envelopes; unfamiliar exceptions (including RPC Error objects if RPC is later reviewed), malformed/oversized replies or contradictory bindings are **non-retryable automatically**, safe internal failure, retaining possibly charged ownership and quarantining possible ACTIVE work. Never retry blindly or decrement on errors. Only a specifically classified transient unavailable/transport case may use the bounded same-operation/original-ticket control budget before the original deadline; no deadline renewal or hidden retries. A separate exact inspect/cancel/settlement recovery under retained authority is not a fresh pipeline retry. Possible commit after timeout remains observed and charged. A future RPC alternative must transport the same canonical bounded strings, not broaden JSON types, and requires independent review plus actual runtime evidence.

## 3. Atomic state and bounded policy

Minimum persistent representation: one versioned, bounded coordinator state under a fixed storage key, containing immutable environment/domain/policy fingerprint; durable monotonic clock high-water mark/window metadata; owner registry; and aggregate/tenant/source usage. One storage transaction reads, validates, expires **unstarted** reservations, checks caps, and writes all related changes atomically. No network/D1 call, request callback or side effect inside a transaction callback; callback retry must be side-effect free. No `allowConcurrency`, `allowUnconfirmed` or memory-only authoritative counters. Resolve grant/start/release responses only after the storage operation is durably acknowledged.

On restart reconstruct charged counters from durable `RESERVED`, `ACTIVE` and `QUARANTINED` records, check consistency against persisted counters and policy, and deny all new work on inconsistency. Never reset state when configuration changes or silently overwrite corrupt/missing metadata in a nonempty registry. Empty first initialization is allowed only under explicit local test bootstrap. No request-side D1 initialization/migration. Remote bootstrap and storage restoration remain separately authorized. DO restore or renaming loses accounting/replay history just as D1 restore can: contain ingress, preserve newest records and prove reconstruction before reopening; do not create a fresh coordinator to clear overload.

Trusted configuration explicitly supplies: aggregate concurrency cap G; uniform tenant cap T (v1 has no tenant policy map); stable-source cap S; maximum tenant/source keys; lifetime owner-record cap R; fixed-window aggregate/tenant/source arrival limits; window duration; unstarted reservation TTL; active diagnostic expiry; bounded control-call attempt budget. Validate positive safe integers and closed environment/action. For local constructors use implementation safety ceilings aligned with existing bounded controls: concurrency/key/record maxima at most 1,024; rate maxima at most 10,000/window; window 1,000–60,000 ms; reservation/diagnostic durations 1–30,000 ms; control-call attempts 1–4. Reject missing, conflicting, above-ceiling or malformed values, including policy changes against existing state. These are **local representation/testing bounds**, not approved production limits; future production policy needs separate review rather than reusing them implicitly.

A clearly labeled fixture may configure G=2, T=1, S=1, key caps=2, R=32 and a 10-second rate window, or larger explicit caps for concurrency/idempotency fixtures. No tenant-specific privileged tier or production default. Staging's proposed 16/4/128 and 100/1,000/10-second numbers remain proposals; do not hardcode them as production policy. Tenant quota is newly tested with synthetic limits, not a commercial quota decision.

For the minimal protocol, the rate quota counts **successful first reservations**, including duplicates/invalid semantic attempts admitted after authentication, not every capacity-denied arrival. This follows staging's admitted-arrival qualification; anonymous and local preauth budgets still handle denied-arrival abuse. One atomic reserve checks rate and concurrency/cardinality and increments all counters once; identical control retries do not recharge. Definite capacity denial returns 503/overloaded; rate denial 429/rate_limited with validated remaining-window Retry-After (1–60); transport outage 503/unavailable; malformed capability results/storage invariants 500/internal. Deadline remains 504 and never renews. No retry hint for leaked/quarantined capacity because its recovery time is unknown.

Window state survives restart. Compare validated coordinator clock against durable high-water mark; rollback/invalid time denies rather than renews windows. Advance a whole fixed window only on valid forward observations; no sliding per-request renewal. Current-window tenant/source maps retain used buckets until rollover; capacity denial must not evict a bucket or steal another tenant's quota. Live charged counts and historical owner records remain independent of window reset. Bound all maps, record fields and diagnostic reads, not only in-memory cache.

Permanent owner tombstones consume R slots. New owners denied at R; duplicates and settlement of **existing** records remain possible at saturation. Historical tenant/source owner associations are included in key bounds; compaction must preserve identity/fence and cannot evict owner handles. No physical deletion, REPLACE, nonce recycling or automatic target reset. This deliberately exhausts a finite synthetic fixture eventually. Long-lived production throughput/retention is **not solved** by this slice; later compaction/retirement policy needs review. Invalid requests allocate nothing. Definitive fresh denials allocate nothing and permit no work; owner stops that control flow, and a later explicit retry uses a new attempt. No caller can demand creation of arbitrary refusal tombstones.

## 4. State diagram and ownership fence

```text
ABSENT -- atomic reserve, caps pass --> RESERVED (charged, immutable owner/fence/deadline)
ABSENT -- cancelUnstarted seals, R space --> CANCELLED (terminal tombstone)
ABSENT -- caps/validation fail --> definitive NO-GRANT (no work, no record)
RESERVED -- start before reservation deadline --> ACTIVE (still charged)
RESERVED -- cancel or deadline observed --> CANCELLED / EXPIRED (terminal, uncharged)
ACTIVE -- diagnostic expiry / uncertain result / owner loss --> QUARANTINED (charged)
ACTIVE / QUARANTINED -- trusted terminal settlement --> RELEASED (terminal, uncharged)
CANCELLED / EXPIRED / RELEASED -- exact duplicate --> same terminal state (never regrant)
any existing state -- mismatched owner/context/fence --> DENY (no mutation/disclosure)
```

Owner fence is immutable record identity plus owner capability, not an expiring lease granting a replacement execution rights. `start` transaction checks RESERVED, exact owner/context and original deadline; only a durably confirmed start lets that *same execution* launch downstream work once. Reservation expiry can free because no downstream work is allowed without ACTIVE acknowledgement, and late start cannot resurrect EXPIRED. If start committed but its acknowledgement is lost, the durable state is ACTIVE, **not** an expirable reservation. An exact repeated start may return its recorded status but never authorizes a replacement execution to launch. Once response deadline/cancellation has occurred, the original execution also must not launch, even if a late acknowledgement arrives.

ACTIVE diagnostic expiry is **not a freeing TTL**. QUARANTINED keeps aggregate/tenant/source charged, accepts late exact-owner settlement, and never reassigns that slot by time. Terminal transitions decrement all charged counters once in the same transaction; repeated settle/release response loss returns the same terminal result without a second decrement. No counters underflow; cannot use a stale/recycled handle to release another owner. Handles/tombstones survive reboot.

**Why a lease/fence alone is insufficient:** current D1 acceptance does not atomically check a coordinator generation/permit token. Checking DO ACTIVE then awaiting a D1 batch is a TOCTOU gap; DO and D1 have no shared transaction. The existing atomic full-authority/tenant/replay-deadline guards are genuine, but do not fence reassigned concurrency permits. Even a final D1 replay deadline is not proof of bounded remote query finalization or old-isolate termination. Therefore expiry, CPU termination, client abort, `waitUntil` expiry, observing a business event, or finding no event does not prove all previously issued D1 work can no longer commit. No automatic active-slot freeing based on any of them.

## 5. Ambiguity, cancellation, outage and reconciliation

Keep the handle and settlement classification captured in the retained pipeline closure until actual settlement; never discard ownership on HTTP timeout or replace it with a new handle during automatic control retry. Same operation/owner/context across at most the configured control attempt budget, within the original request deadline; this budget is separate from unchanged claim and acceptance budgets. Do not retry unfamiliar permanent errors blindly or run an unbounded hidden recovery loop. Observe all losing promises.

| Failure | Required recovery and invariant |
| --- | --- |
| Reserve committed, acknowledgement lost | No start/no nonce/business work without exact grant recovery. Retry/inspect same owner; reserve cannot recharge. If original deadline elapsed, do not start. The reservation can eventually expire unless start already committed. |
| Inspect says absent after failed reserve | Absence alone is not cancellation: a delayed reserve may still commit. `cancelUnstarted` can seal ABSENT with a bounded tombstone if R has space, preventing late reserve. If sealing fails/saturates, report unknown; no work may launch. Late reserve is still only an unstarted reservation. Keep recovery handle, never assert no record from a timed-out RPC. |
| Start committed, acknowledgement lost | ACTIVE remains charged. Same retained owner may resolve control ambiguity only while its original deadline is open and launch latch unused; after timeout no launch. A lost owner/replacement never launches. If no-work can be proven by the retained original owner, settle as known-not-issued; otherwise quarantine. |
| Timeout/abort before start | Stop stage progression; cancel/seal unstarted state or let its reservation expire. Late acknowledgements cannot advance to claim. Local pipeline stays retained until pending control/body/cancellation work settles. |
| Timeout/abort after start or issued D1 batch | Return safe deadline/transport result, but keep charged until confirmed terminal settlement; abort is cooperative and cannot retract a batch. No late downstream stage/new claim/acceptance retry after cancellation. |
| D1 promise resolves with a terminal result and all stages/retries/cancellation are finished | Original owner can settle; response may already be 504. Preserve actual known durable result for authenticated semantic recovery, not in public permit metadata. |
| D1 rejects with response loss/unknown outcome, including retry exhaustion | JavaScript rejection or a finished pipeline promise is **not** proof remote work terminated. Capture uncertain-issued classification before sanitizing errors; quarantine unless trusted adapter evidence establishes every issued unit is terminal. Returning replay success alone does not prove earlier outstanding units stopped. |
| Release committed, acknowledgement lost | Capacity may already be free; retry/inspect same owner only, get RELEASED tombstone. Never decrement locally then replay a new release against another owner. HTTP success already acknowledged from D1 is not turned into a rollback claim by release failure. |
| Coordinator unavailable/malformed | Deny new starts with safe 503/500 before nonce/business writes; never local fallback. Work already ACTIVE may finish under its existing permit; release unavailable leaks capacity until exact recovery. Caller wait and acquisition attempt count are bounded; underlying losing RPCs and cleanup/settlement may remain pending indefinitely, observed/retained with local permits held. No bounded underlying RPC-completion or availability guarantee. |
| Ingress or coordinator isolate loss/reboot | Durable registry survives coordinator restart. Lost Worker ACTIVE ownership is quarantined, not adopted. `ctx.waitUntil` is finite lifecycle support, not proof of remote completion/termination. |

`finally` may always release **local** counters when the actual local pipeline/cancellation settles, as today. Distributed release requires separate trusted settlement classification: `known-not-issued`, `all-issued-terminal`, or `uncertain-issued`. A new narrow per-request tracker must retain all issued unit outcomes across claim/acceptance retries without changing their SQL or budgets. Give the original D1 repository and replay adapter an optional captured per-request operation-observer capability at the actual issued-batch boundary; report issuance, known terminal completion and uncertain transport rejection before existing normalization/classification. Forward through guarded acceptance and claim operations, never replace the original DB binding with an instrumentation wrapper or add a second acceptance implementation. Keep unknown-issued sticky across retries: later successful replay does not clear it. If an adapter cannot expose sufficient evidence, treat any issuance followed by ambiguous failure conservatively as uncertain; do not infer it solely from final HTTP status. Reads can remain tracked for pending pipeline lifetime although they cannot themselves commit business writes. This optional observer and its narrow forwarding are named Phase-2 changes, not implemented here. Known exact-owner settlement/inspection must remain operable even when admission clock rolls back or registry/key caps are saturated; clock faults block new grants/start, not authenticated release of proven-terminal work. Unknown transport outcome is conservative even when an event can be read back; never normalize away uncertainty before tracking it. Attach the actual settling pipeline, including original settlement/release handling whose underlying completion is not bounded, to protected `ctx.waitUntil`; registration failure cancels progression and retains ownership. If release RPC never settles, bound caller wait but retain observed late control work; do not claim completion. No detached module-global recovery work.

Reconciliation is trusted security-gated maintenance, not HTTP admin. It first contains affected ingress and inventories exact environment/domain, owner/fence, D1/replay/outbox state and *all* issued operations. Source revocation guards may prevent new acceptance, but alone do not prove a previously linearized write cannot still finish. Settlement proof must establish there is no outstanding work capable of committing/launching another stage; a trusted original-owner all-work completion barrier can establish it locally. A remote transport timeout, isolate presumed dead, fixed wait, missing row or semantic replay success cannot. If proof cannot be obtained, **remain quarantined** indefinitely. No automatic admin override to reclaim capacity; destructive target retirement/restore requires separate human policy. Phase 2 may test the private maintenance contract with synthetic proof barriers, but cannot claim a real remote termination oracle exists or build a public admin route.

## 6. Environment and acceptance security

Each environment has a distinct trusted namespace/storage identity and one fixed coordinator domain; its persisted marker/policy must match trusted development or staging composition. Binding identity checks cannot detect a malicious wrapper; trusted code must preserve capabilities. ## 10a. Private observer/facade implementation refinement (approved protocol unchanged)

The construction-time facade captures a descriptor-validated exact configuration (`policy`, `namespace`, `database`) and binds the fixed original namespace stub. Each request creates one private execution with an immutable ticket and an observer tied to the exact original database identity. Both original adapters explicitly advertise observer support; distributed composition requires matching support and identity. At each actual batch boundary, issuance is recorded before calling the original bound batch, resolution marks that unit terminal, and rejection marks sticky uncertainty before error normalization. All resolutions are terminal observations; no rejection is used as termination proof. The observer is forwarded per call across every unchanged retry. No database wrapper is introduced.

Only that execution's completion closure can construct settlement: it waits for all issued control work, checks the original handle and issuance ledger, and constructs a fresh barrier internally when every issued batch resolved or none was issued. There is no request-facing `settle(kind)` or caller barrier parameter. Any rejection permanently quarantines that execution even after successful replay. A private launch latch can be consumed only once after exact RESERVED then ACTIVE acknowledgement and a still-open original deadline. Late control promises remain observed and retain local lifetime/capacity; caller deadline is bounded independently. A separate internal maintenance binder accepts only an original branded execution with its captured namespace/database/policy and private sealed all-work ledger; synthetic positive and forged caller objects are rejected. Sticky uncertainty cannot be overridden, including by this binder. There is no remote termination oracle or ingress maintenance method. This is a minimal implementation refinement of sections 2a/5, not a changed normative guarantee.
